1 Engineering principles

Six rules that keep the build fast, compliant, and cheap to run.

1

Ship the loop, not the vision. One pipeline, reused for every use case.

2

Edge + cloud, residency-aware. Voiceprints never leave Uzbekistan.

3

Bilingual from line one. Uzbek is a first-class workstream, not an afterthought.

4

Privacy by construction. Default-off, encrypted, deletable, consented. No secrets in client code.

5

Demo-then-harden. Demo uses cloud STT; production swaps in self-hosted behind the same interface.

6

Interfaces over implementations. Wrap STT / embeddings / LLM so we can swap cloud↔self-hosted freely.

4 The pipeline

Eight steps, one loop. Recall answers target <2s; transcription & briefing run async after the meeting.

1 · Capture

Default-off recording; Silero VAD drops silence; chunked & uploaded over TLS.

2 · Transcribe

STT → timestamped RU/UZ text (cloud now, self-hosted later).

3 · Diarize

Label speakers; owner enrolled via voiceprint (in-country); user can correct.

4 · Index

Chunk → BGE-M3 embeddings → pgvector with time/speaker/lang. Hybrid retrieval.

5 · Distill

(Phase 1+) entities, decisions, commitments → knowledge graph (Graphiti).

6 · Answer

Question → retrieve top-k → LLM answers in RU/UZ with citations (time + speaker).

7 · Brief

Scheduled job → decisions, action items, key quotes → morning push.

8 · Protect

Encrypt, one-tap delete (cascade), consent & residency enforced throughout.

5 The Uzbek speech workstream (the moat)

Russian is largely solved. Uzbek is the work — and the work is the moat. A dedicated R&D track from Phase 1: fine-tune, serve in-country, and gate releases on accuracy.

Data

UzbekVoice ~1,400h + Common Voice ~265h + USC/FeruzaSpeech; grow with consented in-product data.

Model

Fine-tune Whisper (medium→large-v3) on Uzbek; beat ~14% WER baseline; add a meeting LM.

Serve

faster-whisper / CTranslate2 on a Tashkent GPU — residency + amortized cost. Streaming + batch.

Eval harness

Held-out RU+UZ sets; track WER, diarization error, latency, $/hr; gate model promotion.

Milestones: M1 — eval harness + cloud baseline · mid-M1/M2 — first fine-tuned Uzbek model beating baseline · M2/M3 — in-country serving in production (cloud as fallback). On-device Uzbek is a v2 optimization for capable phones only.

6 Phased delivery

Each phase has a gate. The demo is detailed week-by-week; later phases map to the business milestones.

Weeks 1–4 · Phase 0 — Demo

Working demo on off-the-shelf hardware

W1: skeleton (Flutter + FastAPI + pgvector + Redis); capture→Yandex STT→transcript; validate RU + UZ accuracy (critical risk). W2: BGE-M3 embeddings→pgvector; ask flow with cited LLM answers; diarization + owner enrollment. W3: daily briefing; minimal UI; privacy basics (encrypt, delete, default-off). W4: reliability/accuracy pass; put it on the investor; instrument; pitch.

Gate: Investor uses it on real meetings and won't give it back.
0–6 months · Phase 1 — v1 + beta

Production v1 & private beta

In-country infra, auth, multi-tenant, storage lifecycle; IT Park + DB registration; Uzbek STT R&D (harness + first fine-tune); consent/privacy hardened; billing skeleton; hardware design starts; beta 100–500 users.

Gate: Users love it; retention signal.
6–12 months · Phase 2 — Launch

Public launch

Self-hosted Uzbek/Russian STT in production; Payme/Click billing live; first hardware batch + EMC/Uzstandard certs; scale infra; knowledge-graph memory.

Gate: Healthy free→paid conversion + month-4 retention.
12–18 months · Phase 3 — Scale

Scale & expand

Cost/latency optimization; ~$2 personal tier; screen-memory then vision R&D; iOS app; CIS/Turkic expansion prep.

Gate: Series-A metrics or break-even.
